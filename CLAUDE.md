# CLAUDE.md

Guidance for agentic development on this repo with **Claude Code**. Humans follow the same rules.

## What this is
Event-driven shipment-exception handling: deterministic-first router, playbooks, a bounded
tool-calling agent (OpenRouter), and a TypeScript carrier-gateway, on Kafka (Redpanda).
Read `docs/adr/` before changing delivery semantics, routing, guardrails or telemetry.

## Commands
- `make ci` — everything CI runs: ruff, `mypy --strict`, pytest, offline eval gate, failure
  drills, gateway typecheck + vitest. Run it before proposing any change as done.
- `make up && make smoke` — full stack in Docker (needs the daemon running).
- `make eval-live` — real model; costs money. Never run without the user's go-ahead.

## Rules
- Handlers stay pure (`Envelope -> [Outgoing]`); delivery concerns live in `ConsumerRunner`.
- Every consumer is idempotent; every side effect has an idempotency key derived from `case_id`.
- Contracts are versioned. Add fields compatibly or add a new topic version; never edit
  a payload's meaning in place.
- A new agent tool needs: a pydantic args model, a guardrail decision in `guardrails.py`,
  unit tests, and at least one scenario in `evals/scenarios.jsonl`.
- Never weaken a guardrail, budget or routing threshold to make an eval pass. Change the
  ADR first and say so in the PR.
- Tests are hermetic: no network, no API keys, no broker. Use `ScriptedChat`,
  `InMemoryCarrier`, `InMemoryBus`, `httpx.MockTransport`.
- Do not report eval numbers you did not produce in this session; results files are
  generated by `evals/run_eval.py`.
